# RECA Digital — правило результата (утверждено владельцем 22.10.2026)

**Главная цель — довести продуктовую задачу до работающего, проверяемого результата.**

Этот принцип введён после двух случаев ухода в бесконечные проверки и инфраструктурные улучшения.

1. Каждый этап начинается с пользовательского результата, конкретного артефакта и критерия готовности; тестирование — средство, не самостоятельная цель.
2. Не создавать отдельные PR под каждый вспомогательный тест, абстракцию или подготовительный модуль. По умолчанию — один PR на пользовательскую задачу.
3. Минимальные обязательные проверки: безопасность границ и секретов, корректность сборки, работоспособность основного пользовательского сценария. Дополнительные тесты только при конкретном сбое или обоснованном риске.
4. Если проверка прошла — принимать результат и переходить к следующей функции. Не запускать новый цикл проверок уже доказанного без изменений.
5. Не выдавать количество тестов, PR или созданных файлов за прогресс продукта. Метрика — завершённые функциональные задачи.
6. Прежние ограничения остаются: приватный `reca-digital/demo` недоступен без отдельного разрешения; платный Codex требует явного допуска; никаких автоматических merge/deploy/самовольного доступа к секретам.
